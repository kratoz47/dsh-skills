# 生图简报工作流

> 本 skill 只定义**流程骨架**。字段规则看 `prompts/template.md`，规则看 `style/bible.md`，范例看 `style/board/INDEX.md`，画风实例看 `prompts/layers.md`。
> 资产冲突时，以 `$MYTHOS_ROOT` 下的文件为准。

## 配置

生图管线仓库的根目录通过环境变量给：

```bash
export MYTHOS_ROOT="$HOME/dev/mythos-pipeline"
```

下面所有相对路径都相对 `$MYTHOS_ROOT`。生图只在装有凭据的机器上执行。

## 何时用

用户给「场景 / 物体 / 状态」想生图，或说「画一张…」「生成一张…」时。

## 资产

| 用途 | 路径 |
|---|---|
| 模板（12 字段 + 35 类矩阵 + 验收） | `$MYTHOS_ROOT/prompts/template.md` |
| 画风实例（四层） | `$MYTHOS_ROOT/prompts/layers.md` |
| 风格圣经（三条总纲 + 13 规则） | `$MYTHOS_ROOT/style/bible.md` |
| 范例锚点（B1–B20） | `$MYTHOS_ROOT/style/board/INDEX.md` |
| 生成脚本 | `$MYTHOS_ROOT/tools/gen.py` |
| 编译/评审/判定 | `$MYTHOS_ROOT/taste/cli.py` |
| 案例库（检索用） | `$MYTHOS_ROOT/promptforge/search_cases.py` |
| 工业模板（13 套 Seedream 方言） | `$MYTHOS_ROOT/promptforge/templates.md` |

`style/board` 与案例库属于个人资产，公开仓库不带；没有就跳过步骤 2.5，并在出确认卡时说明「无同题材锚点」。

## 流程

### 1. 收主干

用户给场景、物体、状态，可能就一句话。缺的字段**一次问清**（场景在哪 / 什么东西 / 什么状态），不在这一步问审美细节。

### 2. 定题材

从 `template.md` 的题材矩阵找到对应行，确定焦段 / 镜头语言 / 负向追加。

### 2.5 查案例（写稿前必做，有案例库时）

按题材词检索，参考**同题材案例的结构**（不抄词，抄的是「怎么组织画面」）：

```bash
cd "$MYTHOS_ROOT"
python3 promptforge/search_cases.py --q "<题材词>" --top 5 --show-prompt
```

- 题材词示例：信息图 / 海报 / 插画 / 摄影 / 场景 / 电影 / 角色 / 古风 历史 / 建筑 / 电商 / 品牌 / 图标 UI。
- 也查 `promptforge/templates.md` 里对应的那套工业模板（字段框架 + 避坑）。
- 只借鉴结构（主体怎么摆、文字怎么锁、模块怎么分），**不搬运原案例的废词**（8K/masterpiece/品牌名）。

### 3. 跨方向展开（本步是核心，禁止「换个说法试试」）

展开 2–3 个变体，**每个变体在至少一个高权重字段上真正不同**：

- 任务类型（考古图录扫描件 / 数码纪实照片 / 游戏三视图设定稿 / 电影剧照…）
- 媒介与年代
- 光向（硬光左上 45° / 无光平涂 / 暖黄侧光…）
- 色调（仅两色 / 四到六色 / 黑白…）

每个变体必须写明三件事：

1. **改动点**——在哪个高权重字段上变、变成什么；
2. **预期副作用**——会牺牲什么、可能出什么岔子（不是"换个说法"，是"改了会有什么代价"）；
3. **对标锚点**——`style/board/INDEX.md` 里的 B1–B20 之一，说清「借它的什么」。

**判据：两个变体若任务类型相同、只在措辞上不同 = 不合格，重新展开。**

### 4. 勾选

用 `ask_user_question`（multi_select）把变体列给用户勾选。勾选结果决定后续字段怎么填。

### 5. 出确认卡（未经确认不生成）

按 `template.md` 验收段 + 项目确认卡要求，给：

1. 生图目的——用在哪、哪个位置、为什么
2. 12 字段填满（字段 7 拆 7a/7b；系列补字段 12）
3. 拼好的完整提示词
4. 张数、模型、预估耗时
5. 最可能不过的那条结构项（S 项）

**用户确认前，不调 gen.py，不消耗额度。**

### 6. 生成与记录

```bash
cd "$MYTHOS_ROOT"
python3 tools/gen.py --stage draft --log --rules "R3,R11,R12" \
  --tag <层-主体-版本-轮次> --prompt "<确认过的提示词>"
```

出图后按 `template.md` 的验收项（S1–S7 + Q1–Q4）逐条记 0/1，`taste/cli.py verdict --tag ... --status picked|rejected` 记判定。

## 硬约束

- 古画/平涂风格（拓片、壁画、绢画、木刻）一律写「正交投影，不使用焦段」，不写 35/50/85mm——焦段引入透视压缩与景深，破坏平面性。
- 不写实体名，写画面可见的东西（`template.md`「先描述画面」段）。
- 每轮只改一个变量；结构 2 轮 + 质感 2 轮，超了换阶梯不加词。
- 未经确认不调 API。

## 失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 变体之间只是措辞不同 | 没在高权重字段上拉开 | 回到步骤 3 重新展开 |
| 勾选后生成结果跑偏 | 展开时没写预期副作用 | 出图后对照副作用复盘，修正锚点对标 |
| 平涂图出现光晕/立体阴影 | 焦段写错或漏负向 | 补「正交投影」+ 平涂负向 |
| 想「加一个元素」却丢了旧元素 | 图生图不锁细节 | 改用文生图一次写全，或多出多选 |
| 想「精确改一处」却构图漂移 | 文生图不锁构图 | 放弃微调，用 batch 多出多选 |

## 已实测的模型约束（flash 档，2026-11）

- `seed` 不生效：同 prompt 同 seed 跑两次，图完全不同。
- 参考图锁定结构生效（图生图结构误差≈纯文生图的 1/3），但锁图时「加元素」会挤掉旧元素。
- **做不了精细微调**：正确的生产模式是「多出多选」——
  `promptforge/loop.py batch --count 3` 连出多张，人挑一张 `pick`，
  而不是「爬山微调」（`render`/`score`）。
