# 内容评审工作流

本 skill 只定义**流程骨架**。评分标准来自同目录 `rubric.md`，口径与输出格式来自同目录 `review-protocol.md`。
两者冲突时，以这两个文件为准。

## 配置

评审材料（每套账号一份，不进仓库）：

- `rubric.md` 当前版本（本仓库带 v3 模板）
- 对应平台 3 个 benchmark，带 `review_after`
- 账号结构（三条线的受众定义、视觉约定）
- 盲包与历史摘要

## 角色

| 角色 | 职责 | 运行方式 |
|---|---|---|
| **Chair** | 准备盲包、聚合分歧、写最终决定 | 本会话直接执行 |
| **Panelist 1–3** | 独立打分，互不可见 | 独立 subagent |
| **Critic** | 只审理由是否成立，不打分 | 独立 subagent，不复用 Chair 上下文 |

## 前置检查（Checkpoint 0）

- [ ] `rubric.md` 版本与本次评审一致
- [ ] 对应平台 3 个 benchmark 有效（未过 `review_after`）
- [ ] 盲包含**去标识历史摘要**（形式 / 结构 / 从未出现的做法 / 视觉语言）
- [ ] 三者缺一 → 停止，先补齐；不要「先评了再说」

## Step 1 · 准备盲包（Chair）

输入：候选物（不含作者、不含历史数据）+ 历史摘要 + rubric 全文 + benchmarks。
输出：bundle，事实摘录每条标出处，**不出现评价词**。

Checkpoint 1：bundle 中每条事实都有出处；没有「很强 / 不足 / 较好」这类词。

## Step 2 · 三评委并行（Panelist 1–3）

- 三个独立 subagent **同时启动**，互不可见，各给不同视角（受众 / 竞品 / 平台）
- 每人输出：逐项分数 + 每项一句理由 + D1 反对意见
- 任一失败：重试 ≤2 次，仍失败标 `DEGRADED`；**不得用双评委顶替**

Checkpoint 2：三份评分都完整返回，且每份都有 D1。

## Step 3 · 聚合（Chair）

- 逐项列三人分数；**Δ≥2 标红**
- Δ=0 直接取；Δ=1 取低；Δ=2 由 Chair 裁决并写理由
- 按 rubric 判定表执行；**9–11 分强制复评一次**（换评委或补历史摘要）

Checkpoint 3：每个 Δ≥2 的项都有裁决记录；总分与手算一致。

## Step 4 · Critic 复核（独立 subagent）

输入：bundle + 三份评分 + 聚合报告 + rubric。
只做三件事：流程合规性、理据完备性（逐项）、跨项一致性。
三态决议：`endorse` / `challenge` / `block`。`block` → 退回 Step 3，不允许跳过。

Checkpoint 4：Critic 必须点名「哪条理由站不住」，否则视为无效复核。

## Step 5 · 出结论

- 判定：淘汰 / 候选 / 可发布 / 复评
- 必改项：可执行，不是「再优化一下」
- D1 反对意见：至少一条
- 记入 `review-log.md`（自己维护，本仓库不带）

## 不允许的行为

- ❌ 盲包没有历史摘要，却仍给出 R5 / V3 分数
- ❌ 三评委逐项分数完全一致却不检查独立性
- ❌ Critic 复用 Chair 的上下文
- ❌ 跳过 9–11 的强制复评
- ❌ 未填 benchmark 就判「可发布」

## 复评

只重评修改项相关维度，其余沿用原分；结论标 `round: 2`。
